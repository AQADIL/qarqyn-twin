# Готовность QARQYN к пилоту

QARQYN поддерживает работу с производственными данными, проверку сценариев и подготовку решений для инженера. В комплект входит [тестовый набор организаторов](../data/allur.json) за две даты. Подключение к действующему заводу, промышленная точность и фактическая экономия не подтверждены.

## Ограничения

- Модель потока стационарна. Она не описывает разгон, передел, очереди, параллельные линии, межоперационные запасы или пересечение остановок. Минимальный план относится к расчётным минутам при заданных ограничениях, а не к расписанию ремонтных работ.
- Длительность исходной строки организаторов не подтверждена. Восемь часов в примере остаются допущением. Для рабочих данных нужны длительность периода, режим, состав линии и согласованное покрытие качества и простоев. Классификацию событий проверяет инженер.
- Две даты недостаточны для надёжной оценки прогноза. Статистический прогноз не является обученной моделью отказов или диагностикой по датчикам. Историческое покрытие диапазона не гарантирует такое же покрытие в будущем. OEE не рассчитывается без необходимых исходных измерений.
- Существующий ID источника подтверждает наличие записи, но не истинность каждой фразы ИИ. Провайдер получает ограниченный контекст: агрегаты, выборку записей и до шести пар сообщений. Полная история диалога хранится отдельно. SSE передаёт состояние и проверенный ответ, без пословной трансляции непроверенного текста. Отмена не гарантирует отмену уже возникшего списания.
- Сравнение до/после само по себе не доказывает причинный эффект. Финансовый результат зависит от введённых условий и должен сверяться с фактическим спросом, затратами и выпуском. Научная новизна алгоритма и преимущество над другими решениями не подтверждены сравнительным исследованием.
- Иллюстрации служат навигации. Они не являются фотографиями Allur, CAD-моделью или подтверждённой схемой предприятия. [Описание космической темы](cosmic-assets.md).
- История версий не заменяет отдельный архив: удаление набора затрагивает связанную историю. Резервные копии требуют внешнего хранения и проверки восстановления. Корпоративные SSO, MFA, централизованный мониторинг и SLA не входят в автоматически настроенное окружение. Ответственный за инцидент задаётся текстом, без корпоративного каталога. Защита изменённых форм не означает автоматического сохранения всех черновиков.
- Браузерные сценарии не заменяют проверку на целевых мобильных устройствах, полный аудит с экранным диктором, измерение производительности, промышленную нагрузку и длительное испытание устойчивости.

## Условия пилота

1. Согласовать словарь показателей, длительность наблюдения, режимы, маршруты и классификацию простоев. Подтвердить полноту журналов и права на обработку данных.
2. Подготовить сопоставимую историю и интеграцию с источником предприятия. Для MES/PLC нужны протоколы, права доступа и отдельное интеграционное испытание; команды оборудованию приложение не отправляет.
3. Сверить модель с технологической схемой и наблюдаемыми ограничениями. Определить критерии качества прогноза и сценария до оценки результатов.
4. Спланировать измерение до/после, учёт спроса, затрат и посторонних изменений. Фиксировать выполненные мероприятия отдельно от предложенных сценариев.
5. Проверить целевой сервер, настройки доверенного прокси, доступ пользователей, мониторинг, резервное копирование и восстановление. Выполнить нагрузочные, отказные и пользовательские проверки в условиях пилота.

## Воспроизводимая проверка

```bash
npm test
npm run build
npm run test:e2e
```

[Автоматические тесты](../tests) проверяют расчёты, API, импорт и эксплуатационные ограничения. [Браузерные сценарии](../tests/e2e) и [CI](../.github/workflows/ci.yml) предусматривают Chromium, Firefox и WebKit. Результат проверки относится к конкретному запуску и версии кода; успешный запуск не подтверждает промышленную точность или экономический эффект. Тесты контракта ИИ используют контролируемые ответы без платных обращений к провайдеру.
