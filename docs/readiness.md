# Готовность QARQYN к пилоту

QARQYN позволяет пройти путь от производственной записи до проверенного сценария и назначенной работы. В комплект входит [набор организаторов](../data/allur.json) за две даты. Приложение не подключено к действующему заводу; точность на реальной линии и экономия Allur пока не измерены.

## Что доступно

| Задача                         | Реализация                                                                                          | Основание результата                                                                               |
| ------------------------------ | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Найти потери                   | Производство, исходные записи, фильтры дат                                                          | Импортированные данные; отсутствие измерения не заменяется нулём                                   |
| Найти условия целевого выпуска | Стационарная модель и обратный план                                                                 | Расчёт при заданных скорости, качестве и доступном внеплановом времени                             |
| Проверить прогноз              | Отдельная отложенная история, сравнение с последним наблюдением                                     | Выбор метода отделён от контрольного отрезка; недостаток данных показывается явно                  |
| Исследовать оборудование       | Событийная модель, очереди, конечные буферы, НЗП, параллельные станки, передел, интервалы остановок | Параметры вводит и подтверждает инженер; это сценарий, а не измеренная схема Allur                 |

## Что ещё нужно подтвердить

**Прогноз.** На двух датах нет достаточной контрольной истории. Для первого независимого сравнения нужны минимум 16 сопоставимых наблюдений: не менее восьми ранних и восьми контрольных. Устойчивое преимущество требует более длинной проверки и выполнения [явного правила](engineering.md#проверка-прогноза). Это внутренний критерий, а не гарантия будущей точности или оценка вероятности отказа.

**Физическая модель.** Быстрый обратный план остаётся стационарным. Отдельная модель в разделе «Поток линии» учитывает запасы, ожидание, блокировку, одинаковые параллельные станки, заданный передел и перекрытие остановок одного станка. Она использует последовательный маршрут и детерминированные циклы. Списание брака, альтернативные маршруты, наладка и общие ресурсы нескольких участков не моделируются. Параметры и выпуск нужно сверить с реальной линией.

**Мероприятия.** Подтверждение инженера означает принятую к проверке работу, а не уже доказанный эффект. В исходном журнале нет временных отметок остановок: разные события могут пересекаться. Их сумма не объявляется временем простоя всей линии. После обновления данных интерфейс снимает подтверждения загруженного плана и требует повторной проверки.

Неполные данные не мешают подготовить черновик по существующим остановкам. Расчётный эффект остаётся неизвестным, причины показаны явно; передача такого плана в задачи блокируется до исправления исходных условий.

**Экономика.** Известные затраты отделены от неуточнённых. Доход зависит от дополнительного спроса; повторение эффекта предполагает сопоставимые периоды. Налоги, дисконтирование, стоимость запасов и изменение спроса не моделируются. Пилот с измеренным эффектом пока не проведён.

**Эксплуатация.** Реализованы роли, владение, CSRF, аудит, версии, резервные копии и обслуживание SQLite. Для предприятия нужны HTTPS, корпоративный доступ, интеграции, мониторинг, внешнее хранение копий и проверка восстановления. SSO/MFA, отказоустойчивый кластер и промышленная нагрузка не подтверждены. Приложение не отправляет команды оборудованию.

**Интерфейс и ИИ.** Рабочее производство сохраняет автомобильные изображения в обеих темах; космические иллюстрации остаются оформлением главной. Проверка ID источников не гарантирует истинность каждой фразы помощника. Браузерные сценарии не заменяют испытания на целевых устройствах и независимую проверку доступности.

## Условия пилота

1. Согласовать словарь показателей; загрузить историю с длительностью периода, режимом и подтверждённым покрытием журналов.
2. Подтвердить маршрут, циклы, станки, буферы, НЗП, передел и интервалы остановок. Сравнить фактический выпуск с расчётом.
3. Зафиксировать критерии прогноза до проверки. Сохранить отчёт и сравнить результат с простой базой.
4. Обосновать мероприятия, назначить ответственных, согласовать расходы и измерение результата.
5. Сопоставить наблюдения до/после, учесть спрос и посторонние изменения. Только после измерения заявлять производственный и финансовый эффект.

## Воспроизводимая проверка

```bash
npm test
npm run build
npm run test:e2e
```

[Тесты](../tests) проверяют расчёты, права, версии, импорт и эксплуатационные ограничения. [CI](../.github/workflows/ci.yml) запускает также Chromium, Firefox и WebKit. Результат относится к конкретному запуску и коммиту. Контрактные тесты ИИ используют контролируемые ответы без платных вызовов и не измеряют качество внешней модели.
