# Проверки backend и расчётной модели

Документ отражает реализацию на 8 октября 2026 года. Проверки воспроизводятся из репозитория:

```bash
npm test
npm run build
```

На коммите `0fafc67` прошли 110 unit/API-тестов, production-сборка и по 9 браузерных сценариев в Chromium, Firefox и WebKit: [удалённый запуск CI](https://github.com/AQADIL/qarqyn-twin/actions/runs/37793294941). Браузерные сценарии используют отдельную базу и включают мобильную навигацию, XLSX-импорт, версии данных, задачи, сценарии и прокрутку настоящего видео. Автоматические проверки провайдера используют явно заданные ответы внутри тестового процесса и не вызывают платный API. Они проверяют обработку ответов и сбоев, но не качество рассуждения внешней модели.

## Что проверяется

| Область             | Проверяемые свойства                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Наблюдения          | Итоги исходного набора, фильтрация дат, взвешенный брак, отсутствие двойного счёта выпуска                                                        |
| Пропуски            | Отсутствующие план и выпуск остаются неизвестными; неполное качество не превращается в 0% брака                                                   |
| Поток               | Ручные контрольные примеры, неизменность базы при нулевом воздействии, пределы восстановления                                                     |
| Обратный план       | Минимальность, недостижимые цели, потери качества последующих операций, сохранение ТО                                                             |
| Прогноз             | Порог выбора метода, причинный backtest, неизменность прошлых прогнозов при добавлении будущего, физические границы                               |
| Сопоставимость      | Даты и линии, заданные периоды и режимы, сброс истории после смены условий, качество для каждой даты                                              |
| Проверка диапазонов | Прошлое покрытие только по более ранним ошибкам; пропуски и эвристика роста недавней MAE                                                          |
| Неопределённость    | Отсутствие выдуманной MAE на двух датах, различие наблюдаемого диапазона и прошлых ошибок, условность событийного простоя                         |
| Эффект              | Пересчёт частичного восстановления, отсутствие денег без ввода, нулевая маржа, затраты, недостижимая цель                                         |
| Экономика           | Регулярные затраты, ограничение продаж, непроданные единицы, защита от дробных субкопеечных сумм и бесконечной окупаемости                        |
| До/после            | Существующие непересекающиеся даты, нормирование на период и рабочее время, сопоставимость, неизвестные потери и отсутствие причинных утверждений |

| Хранение            | Сохранность SQLite после открытия заново, каскадное удаление, ротация владельца и отзыв сессий                                                    |

## Существенные исправления

- Лаборатория, обратный план, сравнение и помощник используют одинаковый предел восстановления. Плановые и неклассифицированные события исключены; фильтр даты применяется также к ТО.
- Доли брака и границы Уилсона не округляются до расчёта. Регрессионный пример сохраняет потерю 49 единиц на миллион, которая раньше могла исчезнуть после округления процента.
- Расчёт потока требует качество каждой производственной даты каждого участка. Неизвестные потери возвращаются как `null`; настоящий нулевой простой требует подтверждения полноты журнала.
- Несопоставимые даты, несколько линий/строк на период, изменённый режим и противоречивая длительность блокируют стационарную симуляцию. Разрешение импорта для просмотра не означает разрешение любого расчёта.
- Одноимённое оборудование разных участков не объединяется в одну остановку. Условный прогноз событий не заполняет отсутствующие даты нулями.
- Набор требует уникальных ID, существующих ссылок, корректных календарных дат и конечных значений. Изменение не оставляет инциденты со ссылками на удалённые участки.
- Обновление проверяет версию. Контрольная сумма рабочего набора не включает прежнюю контрольную сумму, поэтому повторное сохранение того же содержания устойчиво.
- CSV защищён от формульных префиксов, в том числе после начальных управляющих символов.
- Денежный расчёт требует входных сумм пользователя, учитывает регулярные расходы и заданный предел продаж. Нереализованный выпуск не создаёт доход; неконечные сроки окупаемости остаются неизвестными.
- Прогноз использует историю последнего заданного режима и проверяет интервалы только на будущих относительно калибровки точках. Эти проверки не подменяют промышленную валидацию.
- Инструмент проверки пилота возвращает факты до/после и причины несопоставимости, а не выдуманный успешный результат внедрения.
- Смена данных владельца через окружение обновляет учётную запись при перезапуске и отзывает прежние сессии.
- Учёт платного ИИ сравнивает точные суммы с бюджетом. Неопределённый сетевой исход сохраняет резерв; автоматического платного повтора нет.

## Что эти проверки не доказывают

Пройденные тесты не являются аудитом всех возможных уязвимостей или подтверждением промышленной точности. Требуют отдельной проверки:

- **Пилот и данные.** Нет подтверждённого PLC/MES-подключения и длительной истории завода. Полноту журналов и режим можно вводить в рабочих данных; исходные две даты не содержат этих уточнений. Инструмент до/после не является проведённым заводским пилотом.
- **Физическая модель.** Не учитываются очереди, передел, параллельные линии, межоперационные запасы и перекрытие остановок. Расчётный прирост условен.
- **Экономика.** Ввод пользователя должен отражать реальную маржу, разовые и регулярные затраты, спрос. Налоги, дисконтирование, стоимость запасов и изменение спроса не моделируются.
- **Внешний ИИ.** Существующие ID и корректная структура не гарантируют истинность фразы. Ответы нуждаются в инженерной проверке; вопрос и данные выбранного набора передаются провайдеру.
- **Развёртывание.** Нужны HTTPS, корректный proxy Host, права на файлы, резервное копирование с проверкой восстановления и мониторинг. SQLite и локальные сессии рассчитаны на один экземпляр.
